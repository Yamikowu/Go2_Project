# 專案開發挑戰與問題解決記錄 (Troubleshooting & Challenges)

**專案**：Go2 機器狗視覺系統開發 - 人臉辨識模組
**日期**：2026-05-18

這份文件記錄了從零開始建立跨平台人臉辨識系統的過程中，所遇到的主要技術挑戰、問題原因分析，以及最終的解決方案。

---

## 1. 跨平台通訊與架構問題

### 🔴 挑戰：Mac 無法連線到 Windows 相機伺服器 (Connection Refused)
*   **情境**：在「Windows 擷取影像 -> Mac 進行 AI 運算」的架構下，Mac 端的 Socket Client 一直報錯無法連線。
*   **原因分析**：Windows 電腦同時連線了 VPN，導致 Python 的 `socket` 預設抓取到虛擬網卡的 IP，而不是區域網路的實體 IP。
*   **解決方案**：
    *   使用 `ipconfig` 確認實體網卡的正確 IP (如 `192.168.0.14`)。
    *   在伺服器端強制綁定該 IP，並調整 Windows 防火牆設定允許該 Port 通行。

---

## 2. 效能災難 (The Lagging Issue)

這是開發初期遇到最嚴重的問題，執行一段時間後 Mac 嚴重卡頓，記憶體佔用飆升。

### 🔴 挑戰 2.1：模型過於肥大
*   **原因分析**：初期使用了 InsightFace 的伺服器級大模型 `buffalo_l`，佔用高達 2GB RAM，對於即時邊緣運算負擔太大。
*   **解決方案**：將模型切換為專為邊緣裝置設計的輕量級模型 **`buffalo_s`**。準確度足以應付家用情境，但 RAM 佔用大幅降至 300MB，且模型檔案極小 (約 3MB)。

### 🔴 挑戰 2.2：無意義的重複 I/O 操作
*   **情境**：每次按下 `s` 鍵儲存新臉孔時，程式會卡住好幾秒。
*   **原因分析**：原本的邏輯是每次存檔都會「重新讀取硬碟裡的所有照片」。當資料庫越來越大，讀取時間就越長，造成嚴重的 I/O 瓶頸。
*   **解決方案**：實作**增量更新 (Incremental Load)** 機制。用 `Set` 紀錄已經載入過的檔案路徑，每次更新只讀取「新拍的那張照片」，將存檔動作變成瞬間完成。

### 🔴 挑戰 2.3：每一幀都進行重度運算
*   **原因分析**：相機以 30 FPS 傳送畫面，Mac 每一幀都在全功率執行人臉偵測與特徵比對，導致 CPU 過載。
*   **解決方案**：導入 **Frame Skip (跳幀偵測)** 機制。設定為每 2 幀才進行一次 AI 運算，另一幀直接沿用上一次的結果。這在視覺上依然流暢，但將硬體負擔直接砍半。

## 3. 專案依賴與部署問題

### 🔴 挑戰：AI 模型亂跑，專案無法攜帶 (Portability)
*   **情境**：InsightFace 預設會將下載的模型檔案丟到使用者的 Home 目錄下 (`~/.insightface`)。
*   **原因分析**：這會導致專案資料夾被複製到另一台電腦 (如 Jetson) 時，程式會因為找不到模型而崩潰，或者又要在新環境重新下載。
*   **解決方案**：在初始化模型時，強制指定 `root` 參數指向專案內部的 `camera/models` 資料夾。實現了 **Portable Project (可攜式專案)** 的目標。

### 🔴 挑戰：GitHub 上傳失敗與隱私外洩風險
*   **情境**：使用 Git 推送程式碼時，遇到大檔案限制，且不小心把測試的人臉照片也上傳了。
*   **原因分析**：初期缺乏完善的 `.gitignore` 設定。
*   **解決方案**：建立嚴格的 `.gitignore` 規則：
    *   阻擋 `camera/models/` (模型檔案太大且為依賴項)。
    *   阻擋 `camera/faces_db/` (隱私資料)。
    *   阻擋 `camera/screenshots/` (測試產物)。

## 4. 系統邏輯與使用者體驗 (UX)

### 🔴 挑戰：「刪除使用者」功能導致資料不一致 (幽靈資料)
*   **情境**：實作了按 `d` 鍵刪除畫面上使用者的功能，硬碟裡的資料夾確實刪除了，但畫面上依然顯示該使用者的名字。
*   **原因分析**：雖然刪除了實體檔案，但 Python 記憶體 (RAM) 裡的全域變數 (`known_faces`) 依然保留著該使用者的特徵向量。且因為「增量更新」機制的關係，程式以為已經讀過就不會去理會。
*   **解決方案**：修改資料庫載入邏輯，加入 `force_reload=True` 參數。當執行刪除動作後，強制清空記憶體並重新掃描硬碟，確保「硬碟與記憶體狀態同步」。

### 🔴 挑戰：測試不便，過度依賴 Windows 環境
*   **情境**：每次要改一點程式碼，都必須把 Windows 開起來跑 Server 才能測試。
*   **解決方案**：開發了平行版本的 `camera/demo/face_rec_local.py`。共用同一套核心邏輯，但將影像來源改為 Mac 內建相機或 iPhone 接續互通相機，大幅提升了開發效率。
