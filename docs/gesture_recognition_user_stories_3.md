# 手勢辨識模組使用者故事對應表（3 個精簡版）

> 對應檔案：`camera/demo/gesture_recognition.py`

## 1.1 啟動攝影機並接收即時影像

**名稱**  
1.1 啟動攝影機並接收即時影像

**類別**  
User Story

**角色**  
互動使用者

**需求**  
系統能成功啟動攝影機並持續接收即時畫面，作為手勢辨識的輸入來源。

**價值**  
提供後續手部偵測與手勢辨識所需的原始影像資料，確保整體流程可以正常運作。

**接受條件**  
- Given：使用者已開啟程式，且裝置攝影機可正常使用。  
- When：系統執行攝影機初始化與影像讀取流程時。  
- Then：系統應成功取得連續影像畫面，供後續辨識模組使用。  
- Then：若無法取得畫面，系統應顯示錯誤訊息提醒使用者確認相機權限或裝置狀態。

**優先順序**  
1

---

## 1.2 偵測手部並判斷手勢

**名稱**  
1.2 偵測手部並判斷手勢

**類別**  
User Story

**角色**  
互動使用者

**需求**  
系統能從即時影像中偵測手部關鍵點，分析五根手指狀態，並判斷出對應的手勢名稱。

**價值**  
讓系統可以將畫面中的手部動作轉換為可辨識的手勢資訊，作為互動控制或後續功能決策的依據。

**接受條件**  
- Given：系統已成功接收一幀包含手部的影像資料。  
- When：系統將影像送入手部偵測與手勢判斷流程時。  
- Then：系統應能辨識手部關鍵點，並分析五根手指的伸直或彎曲狀態。  
- Then：系統應輸出對應的手勢名稱，例如 `One`、`Two`、`Good`、`Five`。  
- Then：若畫面中沒有手部或手勢不屬於既有定義，系統應回傳預設值，如 `None` 或 `Unknown`。

**優先順序**  
1

---

## 1.3 即時顯示辨識結果並支援安全退出

**名稱**  
1.3 即時顯示辨識結果並支援安全退出

**類別**  
User Story

**角色**  
互動使用者

**需求**  
系統能將辨識到的手勢名稱即時顯示在畫面上，並允許我透過按鍵安全結束程式。

**價值**  
讓使用者能立即確認辨識結果，同時確保測試流程可以正常結束，不留下攝影機資源占用問題。

**接受條件**  
- Given：系統已持續執行手勢辨識流程。  
- When：系統完成每一幀的手勢辨識後。  
- Then：系統應在畫面上顯示目前的辨識結果。  
- Then：系統應透過連續多幀結果穩定化輸出，避免辨識結果頻繁閃爍。  
- Then：當使用者按下 `q` 鍵時，系統應正常釋放攝影機資源並關閉視窗。

**優先順序**  
2

## Epic

**名稱**  
3. 手勢辨識

**類別**  
Epic

**角色**  
操作者／互動使用者

**需求**  
機器狗能透過攝影機主動辨識使用者的手部動作與手勢狀態，並將辨識結果即時顯示於操作畫面或提供後續互動模組使用。

**價值**  
賦予機器狗理解使用者手勢指令與互動意圖的能力，使其能根據不同手勢做出對應反應，提升人機互動的直覺性、即時性與操作便利性。

**接受條件**  
- Given：系統已成功開啟攝影機，且手部偵測與手勢辨識模組已完成初始化。  
- When：使用者出現在攝影機視野內，並做出指定手勢動作時。  
- Then：系統應能偵測手部關鍵點、分析五根手指狀態，並準確辨識對應的手勢類型。  
- Then：系統應將辨識結果即時顯示於畫面上，或提供給後續控制與互動模組使用。  
- Then：系統應在連續影像輸入下維持穩定輸出，避免手勢結果頻繁跳動或錯誤切換。

**優先順序**  
1
